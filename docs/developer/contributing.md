# Contributing

Contributions are welcome: bug reports, questions, validation cases, documentation and code. Open an issue on
[GitHub](https://github.com/bsafdi/axionFEM/issues) to report a problem or discuss a change before a large pull
request. AI coding agents are welcome too; [AGENTS.md](https://github.com/bsafdi/axionFEM/blob/main/AGENTS.md) gives
them the same conventions as this page.

## Reporting a problem

Include the axionFEM version and `af.build_info()`, the design (JSON) or a short script that shows the problem, the
full error message, and what you expected. For a numerical question, include the element order and mesh settings and
whether the result changes under refinement.

## Pull requests

A pull request should:

- **pass the tests**: `ctest` and the pytest suite on your build, and the [quick subset](testing.md#the-quick-subset)
  for changes to solvers or physics;
- **add tests** for new behaviour, comparing with an independent reference (closed form, manufactured solution,
  second formulation or published result);
- **show validation for new physics**: a convergence study and the comparison, in a validation page or the test;
- **label what is not validated** as beta, in the docstring, the docs and any warning the code prints;
- **update the documentation**: the user-guide page, the physics or validation page, and `llms.txt` when the public
  API changes;
- **add a CHANGELOG entry**;
- **never hand-edit generated numbers**: records, figures and captions are regenerated by their scripts.

## Code style

- **C++17** in `cpp/`, namespace `axf`; Python 3.10+ in `python/axionfem`.
- **Comments explain what the code does and why**, in the present tense, with the physics or numerics reasoning that
  is not obvious from the code. They do not narrate history.
- **Errors say what is wrong, where (the JSON path) and how to fix it.** Users and agents act on them.
- **Units.** SI inside; natural units only where labelled.
- **Results carry diagnostics** (mesh, unknowns, residuals) and at least one independent consistency check; prefer
  exact formulations (elimination, exact boundary maps) over penalties.

## Dependencies and licences

axionFEM is BSD-3-Clause. Code linked into it must have a permissive licence (BSD, MIT, Apache, MPL); GPL software may
be used only as a separate program, as gmsh is through `axf-mesher`. The vendored three.js in `viewer/vendor` is
never modified; its checksums are tested.

## Documentation

The site builds with `mkdocs build --strict` ([Documentation and figures](docs.md)). Pages keep their paths, since
code, tests and other pages link to them; navigation titles are set in `mkdocs.yml`.
