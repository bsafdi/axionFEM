# 3D designs, MPI and clusters

Axisymmetric models are exact for rotationally symmetric geometry and excitation, and cost seconds. Real detectors
break the symmetry: a pickup slit fed at one point, a readout port, support structures, a tuning rod off the axis.
The 3D engine solves the same problems in full 3D (H(curl) elements, an exact open boundary through an
infinity-shell map, hypre AMS preconditioning) on MPI ranks.

The 3D engine needs the [MPI source build](install.md#mpi-source-build). The wheels and the sequential build do not
have it: `af.build_info()["engine_3d"]` is then `False`, and a 3D design stops with an error that says so.

## From an axisymmetric design to 3D

`axionfem.convert.to_3d` revolves every region of an axisymmetric design about the z axis. The pickup can stay the
ideal slit of the axisymmetric model, so that the 2D and 3D results are directly comparable, or become a real slit
with a feeding port:

```python
import axionfem as af
from axionfem.convert import to_3d

d = af.template("toroid", R=1.0, H=1.0, tw=0.06, g=0.04, ts=0.05, f=0.06)   # layers a coarse 3D mesh resolves
d3 = to_3d(d, mesh={"size": 0.45, "surface_size": 0.18, "order": 1})        # ideal slit (default)
res3 = d3.solve("runs/toroid_3d", mpi_ranks=4, verbose=0)
res2 = d.solve("runs/toroid_2d", verbose=0)
print(res3.Psi, res3.L_p)
print(res3.Psi / res2.Psi - 1, res3.L_p / res2.L_p - 1)                    # 3D against axisymmetric
```

`to_3d(d, pickup="slit", slit_deg=4.0)` cuts a real meridional slit of that angle in the pickup sheath and feeds the
readout current through a port in the slit; the result then depends on how the port feeds the current: for the
toroid sheath, Ψ and L_p lie 1 to 3 % above the ideal slit, and the difference does not vanish under refinement
([3D against axisymmetric](../validation/m2_3d_vs_2d.md)). Zero-thickness curves cannot be revolved: model sheets
as thin regions. A 3D design can also be written directly with `"symmetry": "3d"` and solids (see the 3D sections
of the [design format](../design_format.md)).

The mesh settings above are deliberately coarse, for a first run: first-order elements and a surface size of 18 cm,
which still resolves the 4 to 6 cm layers of this toroid (the quick-start toroid's 1 to 2 cm layers need a finer
surface mesh). 3D results need the same convergence check as 2D ones (element order and mesh size,
[Concepts](concepts.md#convergence)). The last line compares with the axisymmetric solve: on this first-order mesh
Ψ and L_p differ from it by a few per cent, and with second-order elements and finer meshes the 3D result at the
ideal slit approaches it ([3D against axisymmetric](../validation/m2_3d_vs_2d.md)).

## Running on several ranks

- **From Python**, `Design.solve(mpi_ranks=N)` runs `axf solve --save` on N ranks and loads the saved solution, so
  sampling, scenes and plots work as after a single-process solve. Without `mpi_ranks`, a 3D design runs in the
  Python process on one rank.
- **From the command line**, `mpirun -n N axf solve design.json -o run` (or `srun -n N ...` in a SLURM job).
- **The launcher.** `Design.solve` uses `$AXF_MPI_LAUNCHER` if it is set (it may carry options, for example
  `"srun --mpi=pmix"`), else `srun` inside a SLURM job when `srun` is on `PATH`, else `mpirun`, else `mpiexec`; the
  `launcher` argument overrides it for one call. From inside an `srun` step (an interactive `srun --pty bash`, for
  example) set `AXF_MPI_LAUNCHER="srun --overlap"`, or the inner `srun` waits for resources the outer step holds.
- **Threads and ranks.** Each rank uses `OMP_NUM_THREADS` OpenMP threads; keep ranks × threads at or below the cores
  of the allocation.
- **Memory** grows quickly with the element order and the number of unknowns. Start coarse (order 1, a coarse
  `mesh.size`), check the unknowns that `res3.data["mesh"]` reports, then refine.
- **Saving and reloading.** `res3.save()` (or `axf solve --save`) writes the solved fields into `<run>/fields`
  and returns that directory; `af.load_solution("runs/toroid_3d/fields")` loads them later for sampling and scenes
  without solving again.
- **ParaView.** `res3.write_vtu("toroid.vtu")` (or `axf solve --vtu`) writes the fields for ParaView; `res3.show()` and
  `res3.export_html()` display them in the viewer ([Visualization](visualization.md)).

## Batch jobs

On a cluster, compile and run inside job allocations, with the same compiler and MPI loaded as for the build
(`source scripts/env.sh`; site setup such as `module load` lines can go in a file named by `AXF_ENV_HOOK`). A minimal
SLURM script for a 3D solve, with the account, partition and sizes to fill in for your site:

```bash
#!/bin/bash
#SBATCH --account=YOUR_ACCOUNT
#SBATCH --partition=YOUR_PARTITION
#SBATCH --nodes=1
#SBATCH --ntasks=16
#SBATCH --cpus-per-task=4
#SBATCH --time=02:00:00
export SLURM_EXPORT_ENV=ALL                # pass AXF_* and OMP_* to the ranks
export OMP_NUM_THREADS=$SLURM_CPUS_PER_TASK
source scripts/env.sh                      # with AXF_ENV_HOOK naming your module loads, if any
srun -n "$SLURM_NTASKS" ./build/axf solve design.json -o run --save
```

Some sites start `srun` steps with `SLURM_EXPORT_ENV=NONE`, which drops the `AXF_*` and `OMP_*` variables from the
ranks; the `export` line above restores them (`Design.solve` sets it for the ranks it starts). The repository's
[scripts/slurm/](https://github.com/bsafdi/axionFEM/tree/main/scripts/slurm) folder has two more examples of the
same form, which run the test suite and its quick subset ([Running the tests](../developer/testing.md)).

## Troubleshooting

| symptom | cause and fix |
|---|---|
| `the 3D engine is not available in this build` | a wheel or a sequential build: use the MPI source build. |
| every rank reports itself as rank 0 of 1 | the launcher does not match the MPI the build uses (for example Ubuntu 24.04's MPICH package): use OpenMPI there, or name the launcher in `AXF_MPI_LAUNCHER`. |
| an `srun` inside an interactive allocation hangs | set `AXF_MPI_LAUNCHER="srun --overlap"`. |
| OpenMPI warnings about UCX or InfiniBand on a single machine | `export OMPI_MCA_pml=ob1 OMPI_MCA_btl=self,vader` (OpenMPI 5: `self,sm`) selects the shared-memory transport; Python sessions set these by default for the MPI they start. |
| `3D mesh generation failed` (the mesher log reports intersecting segments and facets) | the surface mesh is too coarse for the thinnest layer: lower `mesh.surface_size`, or a region's own `surface_size`, below the layer thickness. |
| a solve that does not converge | the warning or the error's hint includes a check of the worst mesh elements; inverted or degenerate curved elements usually point to a coarse surface mesh at a curved boundary. |
